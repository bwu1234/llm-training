Model architecture explorer

GPT-2 and Qwen3 side by side, traced from this repository's own model code. Each row is something that actually runs in one forward pass, in the order it runs: a module, a function such as RoPE's apply_rope, or a tensor operation, with its output shape and parameter count. Operations that together do one thing are one row: LayerNorm's “Normalize” opens to its sub, add, sqrt and div. Select a row to read what it does and the code that does it. Selecting a module also highlights the module at the same path in the other model.

ShapesB is the batch size and T the number of tokens. Every other dimension is the preset's own number.
StepsRows in this colour are operations the repo's own code performs: residual additions, the head split, RoPE, causal masking, the SwiGLU multiply. Inside a PyTorch module such as Linear, the module row is the step. Buffers, such as RoPE's cos and sin tables, are listed under the module that stores them. Selecting a row marks where its inputs come from (teal edge) and what reads its output (orange edge).
Where this comes fromEach model is built on PyTorch's meta device and traced with module hooks, Python's sys.monitoring for function calls, and PyTorch's function and dispatch modes. Generation fails if any kernel runs outside a recorded step or module, so no step is left out. Regenerate with uv run python -m llm_training.explain.
